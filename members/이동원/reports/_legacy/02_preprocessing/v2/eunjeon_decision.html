02eunjeon이란 무엇인가 — python-mecab-ko와의 관계 (웹크롤링 결과)

역사적 관계

"은전한닢 프로젝트"(Eunjeon Project)는 일본어 mecab을 한국어로 적응시킨 프로젝트. mecab-ko native binary 자체가 Eunjeon Project의 산출물. 즉 eunjeon과 python-mecab-ko는 같은 native binary를 다른 Python wrapper로 노출하는 형제 관계.

세 wrapper 모두 같은 mecab-ko + mecab-ko-dic을 호출하므로 POS 태그·morphs·nouns 출력은 동일. 차이는 (a) 설치 절차, (b) 함수 인자 옵션(dicpath 등), (c) 사용자 사전 등록 인터페이스뿐. 본 ESG 분석 결과 quality에는 영향 없음.

04eunjeon 사용이 좋은 결과에 반드시 필요한가? — 사용자 핵심 질문 답변

질문 1: eunjeon을 사용해야 좋은 결과를 얻을 수 있는가?

❌ 아니오 — python-mecab-ko가 동일 native binary 사용, 결과 동일
  • 두 wrapper 모두 mecab-ko + mecab-ko-dic native 호출 → 출력 토큰·POS 동일
  • 본 ESG 분석에서 (seed TF-IDF / FastText / cosine / Spearman) 어느 단계도 wrapper 차이에 영향 받지 않음
  • 학술 인용 시에도 "Mecab 사용"으로 충분 (Park & Cha 2014). 특정 wrapper 명시 불필요

질문 2: eunjeon이 가이드 또는 기말 프로젝트에 문제를 발생시키는가?

⚠️ 직접 위반은 아니지만, 가이드 04 §2-1 재현성을 약화시킴
  • 가이드 04 §1: 제출물 = .ipynb + .md. eunjeon 자체는 제출물 외
  • 가이드 04 §2-1: "위→아래 실행 시 재현" — eunjeon 의존 시 채점자 환경에서 C++ 빌드 도구 + 추가 시간 필요
  • 가이드 04 §3 "재현성 관련: 노트북 실행 순서, 출력 표, API key 제거 상태가 확인되어야 합니다" — eunjeon은 환경 의존도 ↑ → 위 §3 항목 충족 어려움
  • 위반금지 8항목 직접 위반은 없음. 다만 진단(#6)·평가 기준(#8) 항목에서 "eunjeon 미설치 시 결과 다름" 가능성 ❌ (실제로는 동일 출력이므로 다르지 않음)

질문 3: 다른 팀원도 설치해야 한다면 비권장?

✅ 정확. 비권장. 팀 + 채점자 모두 동일 부담
  • 팀 4명: 각자 본인 환경에서 02 노트북 실행 가능해야 함 (members/{이름}/notebooks/02_preprocessing/)
  • eunjeon 추가 시: 4명 모두 MSVC Build Tools 설치 + 빌드 시간 + 권한 문제 디버깅
  • 채점자: 본 ipynb 받아 Run All 시 동일 부담
  • 이는 가이드 04 §2-1 "self-contained 재현성" 정신과 정확히 반대 방향
