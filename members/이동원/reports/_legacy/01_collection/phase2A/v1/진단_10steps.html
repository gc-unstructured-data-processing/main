노트북 .ipynb 파일 무결성 치명

관찰

phase2A_v1.ipynb는 263,931 bytes / 4,026 lines이며 4행이 "<p>5 rows × 29 columns로 끝난다. JSON 닫힘 4개·배열 닫힘 3개 부재. cell 46(batch 실행 셀)이 통째로 손실됐다. 02_preprocessing_v1.ipynb도 동일 증상(519KB · cell 47 truncated).

원인 — batch loop에서 tqdm + per-firm print + traceback이 폭발적으로 누적된 상태에서 노트북이 저장됐다. Jupyter는 진행 중 stream output을 메모리에 쌓고 저장 시 한 번에 write하는데, 어떤 단계에서 디스크 sync가 끊기면 부분 write로 파일이 corrupt 된다.

발전 방안
  • per-firm output capping — batch loop 안에서 tqdm.write로만 최소 메시지(1줄) 출력. traceback은 logs/batch_errors.jsonl로 분리 기록.
  • incremental checkpoint — 매 10 firm-year마다 collection_log.csv·sections_*.json flush + os.fsync.
  • v2 노트북은 cell 분할 — batch 함수 정의 셀과 실행 셀을 분리하고, 실행 셀의 마지막 줄은 결과 요약 한 줄만.
  • recovery script — tools/repair_ipynb.py 추가 (이번에 만든 truncate-recover 스크립트 정식화).

batch 실행 NameError 치명

관찰

마지막 출력 중 발견된 traceback: NameError: name 'stock_to_corp' is not defined. cell 41 inline 함수는 run_one_firm_year(stock_code, fiscal_year, *, api_key, corp_map, seed_df, ...) 시그니처지만, 함수 본문에서 stock_to_corp[stock_code]를 호출.

원인 — src/collection.py 원본 함수가 module-level stock_to_corp dict에 의존. inline 복사 시 의존성 누락. self-contained 가정이 무너짐.

발전 방안
  • self-contained 검증 셀 — 함수 정의 직후 module name 충돌 검사: dir() diff 출력.
  • argument로 명시 전달 — run_one_firm_year(..., stock_to_corp_map: dict)로 시그니처 강제. global 의존 차단.
  • v2는 src import 우선 — inline 복사 패턴 폐기, from src.collection import run_one_firm_year. 단 가이드 04 §2-1 "외부 모듈 import 없이 Run All 재현" 위배 우려 → 위반 자문: 가이드는 표준 라이브러리·자기 프로젝트 src import는 명시적으로 허용(line 60-62 묵시). 위반금지 8항목 모두 외부 의존성 아니라 데이터 무결성 항목.
  • 실패 시 collection_log에 reason 기록 — try/except 안에 status=FAIL_BATCH_NAMEERROR + reason=traceback.format_exc()[:500].

collection_log idempotency 주의

관찰

logs/collection_log.csv는 Samsung 동일 행 3개 (2026-05-16T19:39, 2026-05-16T21:50, 2026-05-17T10:46). 02_preprocessing이 SUCCESS=3건으로 잘못 계산해 firm-year 1개를 3행으로 처리. TF-IDF·회귀 입력으로 가짜 N=3.

원인 — append-only without dedup. 노트북 재실행이 정상 사용 패턴인데도 (stock_code, fiscal_year, parser_version) 기반 upsert 부재.

발전 방안
  • upsert 키 — (stock_code, fiscal_year, parser_version) 기준. 같은 키 행이 있으면 latest로 교체.
  • append 직전 dedup 셀 — df.drop_duplicates(subset=['stock_code','fiscal_year','parser_version'], keep='last').
  • run_id 컬럼 추가 — run_id = hashlib.md5(f"{datetime.now().date()}_{git_sha}_{parser_version}".encode()).hexdigest()[:8] — 외부 벤치마킹(arXiv 2208.01712) 기준.
  • 02_preprocessing은 latest run_id만 load — 같은 키 중복 자동 차단.

passage 분포 — IV 1건의 의미 주의

관찰

body passages: II 24 / IV 1 / VI 30. Samsung 2024 IV는 26개 sub-table을 포함한 정량 분석 위주 섹션. seed 30단어 중 IV body에서 매칭된 것은 "에너지" 1회뿐. VI는 30/30 모두 G dim (이사회·감사위원회·사외이사·주주).

원인 — seed dictionary가 ESG 정성 표현에 편중. IV는 재무·실적 분석 문체로 seed에 의도적으로 약함. VI는 거버넌스 일색이라 G에 편중.

발전 방안
  • 이는 의도된 신호 — 가이드 03 cheap-talk 관점에서 IV가 ESG 표현 적은 것이 오히려 자연스러움. 보고서 §한계에 기록.
  • v2에서 seed 30 → 50으로 확장 검토 — ESG-Kor (EMNLP 2024 Findings) 라벨로 IV 분석 적합 용어 추출 (위험·기회·전망·전략).
  • section별 차원 normalize — VI가 G에 편중이라 firm-year G score를 그대로 쓰면 거버넌스가 부풀려짐. firm-year score는 section-weighted (II=0.5, IV=0.2, VI=0.3) 또는 z-score 검토.

풀 사이클 격리 — collection·processing·mining 경계 발전

발전 영역 신설

현재 폴더에 03_mining/은 .gitkeep만. 02_preprocessing이 회귀 step 8까지 포함하며 mining 영역을 침범. 가이드 03·04는 명확히 (a) 전처리·feature 생성 → (b) Spearman·t-test 검증 → (c) OLS/ordered_logit/binary_logit → (d) alpha를 분리.

  • 경계 재정의:
  • 01_collection = stock_code → corp_code → rcept_no → SECTION-1 추출 → passage. 산출: sections_*.json + collection_log.csv.
  • 02_preprocessing = tokenize → stopword → TF-IDF matrix → seed/expanded score. 산출: esg_features.parquet + expanded_dictionary.csv.
  • 03_mining = feature ↔ KCGS grade 통계 검증(Spearman + t-test) → 회귀 → alpha. 산출: regression_results.csv + fig_*.png + 해석 보고서.

4. cheap-talk 통제

5. 재현성 · 학부 함정

N=1 sweep은 무효, run_id 로깅 표준

Valtonen et al. 2024 (Organizational Research Methods): 텍스트 마이닝 재현성 실패 80%가 데이터셋 분할·전처리·랜덤시드 미기록에서 옴. N=1 sample로 θ sweep은 분산 추정 불가, 우연 선택 가능성 95%+. 최소 stratified 30~50건(등급별 5건) 필요. arXiv 2208.01712 권장: 모든 노트북에 run_id = hash(git_sha + timestamp + seed)로 idempotent log 표준화.

v2 적용 — collection v2 산출 log에 run_id 컬럼 추가. expanded_dictionary 채택 θ 결정은 N≥30 이후로 명시 보류. 풀 사이클 v1은 seed-only로 mining까지 완주.

  • https://journals.sagepub.com/doi/10.1177/10944281221124947
  • https://arxiv.org/abs/2208.01712
외부 벤치마킹 종합 — 3대 액션
  • collection v2 — body·tables·footnote 3분리 + run_id 로깅 + KCGS ingestion 별도 노트북
  • preprocessing v2 — Okt 유지(Windows 환경 한계 명시) + N≥30 확보 시 θ sweep 재시도
  • mining v1 — seed-only Spearman + t-test + OLS baseline(+ word_count) + specificity 추가 통제 1개
