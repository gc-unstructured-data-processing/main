03근본 원인 — 정규식 텍스트 매칭의 한계

사업보고서 텍스트는 3개 영역에 같은 헤딩이 반복됨

영역pos 대략특징예시
① 표지 + 요약 + 목차0 ~ 15K"II", "III", "VII" 등이 목차 항목으로 등장. 짧은 줄·점선 많음"III. 재무에 관한 사항 .................. 7", "VI. 이사회 등 ...... 245"
② 본문15K ~ 300K+각 섹션이 순서대로 등장 (II → III → IV → V → VI → VII)"II. 사업의 내용 1. 사업의 개요 당사는..."
③ 참조·각주섹션 내 곳곳"...Ⅱ. 사업의 내용을 참고하시기 바랍니다" 같은 cross-reference요약 부분에서 본문 II로의 참조

그래서 정규식이 헷갈리는 이유

  • VI: 주주에 관한 사항 매칭 → 목차의 "VI. 이사회 등 ..." 다음에 "VII. 주주에 관한 사항"이 있는데, 우리 패턴 fallback이 "주주에 관한 사항"만 매칭해서 VI를 VII 자리에 잡음
  • III: pos=5,197은 목차에서 매칭된 위치 (본문 III는 훨씬 뒤에 있음)
  • 한국어 사업보고서는 표기 변형이 많아 정규식 6~8개로도 부족
핵심 통찰: 우리는 본문이 평탄한 텍스트라고 가정하고 정규식으로 잘랐지만, DART XML은 처음부터 SECTION-1 / SECTION-2 / TITLE로 구조화돼 있었음. 우리는 풍부한 마크업을 itertext()로 평탄화한 뒤, 그 평탄화된 텍스트에서 헤딩을 다시 찾으려 한 것 — 자기 발등 찍기.

04벤치마킹 — dart-fss-text 라이브러리 (Jaepil Choi)

웹 크롤링으로 발견한 dart-fss-text는 우리가 풀려는 정확히 그 문제(DART 사업보고서 섹션별 텍스트 추출)를 위한 라이브러리입니다.

핵심 설계 (README 발췌)

  • section_code 체계 — 020000=II 사업의 내용 / 020100=II.1 사업의 개요 / ... 계층적 6자리 코드
  • SectionDocument 스키마: section_code, section_title, level, section_path, text, char_count, word_count
  • XML 파싱 + 정규식 + fuzzy matching 조합으로 섹션 추출
  • 표는 텍스트로 평탄화 (MVP) — 표 셀을 그대로 텍스트에 포함
  • UTF-8/EUC-KR 인코딩 폴백 (오래된 보고서 대응)
  • XML 속성에 무관하게 작동 — 텍스트 기반 매칭 + XML 속성 보조 (2010-2024 전 기간 호환)
  • 의존성: lxml ≥ 6.0.2, pydantic, pyyaml (toc.yaml로 섹션 코드 사전)

06v4 해결 방안 — lxml + SECTION-1 직접 추출

접근 변경 — "텍스트 정규식" → "XML 구조 순회"

❌ v3 (현재) 접근

  1. XML 전체를 itertext()로 평탄화
  2. 평탄화된 텍스트에서 정규식으로 헤딩 찾기
  3. 본문 위치(≥ 5,000자)만 사용
  4. 섹션별 슬라이싱

→ 목차·요약·본문 구분 불가 → 위치 뒤죽박죽

✅ v4 (제안) 접근

  1. lxml로 XML 파싱 (recover=True, huge_tree=True)
  2. root.findall('.//SECTION-1')로 14개 노드 추출
  3. 각 SECTION-1의 첫 TITLE 텍스트로 식별 ("II. 사업의 내용" 등)
  4. 해당 SECTION-1 노드 안에서만 itertext() → 표·본문 모두 포함된 텍스트

→ 목차·요약 자동 배제, 본문 구조 그대로 사용

v4 핵심 함수 (의사 코드)

def extract_sections_v4(xml_text: str) -> dict:
    """SECTION-1 노드 직접 순회 + TITLE 텍스트 매칭 + AASSOCNOTE 보조."""
    root = etree.fromstring(xml_text.encode(), etree.XMLParser(recover=True, huge_tree=True))

    # Roman → label 매핑 (한국어 회사도 ENG="II." 영문이 더 견고)
    label_patterns = {
        'II':  [r'^II\.', r'^Ⅱ\.', r'^2\.', r'사업의\s*내용'],
        'IV':  [r'^IV\.', r'^Ⅳ\.', r'^4\.', r'이사의\s*경영진단'],
        'VI':  [r'^VI\.', r'^Ⅵ\.', r'^6\.', r'이사회\s*등\s*회사의\s*기관'],
        # ... III, V, VII 도 추가
    }

    sections = {}
    for s1 in root.findall('.//SECTION-1'):
        title_el = s1.find('.//TITLE')
        if title_el is None: continue
        title_text = (title_el.text or '').strip()

        # 1) AASSOCNOTE 우선 (D-0-2-0-0 → II)
        aassoc = title_el.get('AASSOCNOTE', '')
        label = parse_aassocnote(aassoc)  # 'D-0-2-0-0' → 'II'

        # 2) AASSOCNOTE 빈 값이면 TITLE 텍스트 매칭 (VI 케이스)
        if not label:
            for k, patterns in label_patterns.items():
                if any(re.search(p, title_text) for p in patterns):
                    label = k
                    break

        if label in ('II', 'IV', 'VI'):  # ESG target
            # 표·본문 모두 포함된 텍스트 추출
            text = ' '.join(t.strip() for t in s1.itertext() if t.strip())
            sections[label] = {
                'section_code': label_to_code(label),  # II → '020000'
                'section_title': title_text,
                'text': text,
                'char_count': len(text),
                'word_count': len(text.split()),
            }
    return sections
