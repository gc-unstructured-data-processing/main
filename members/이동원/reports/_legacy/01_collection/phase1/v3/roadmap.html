🚨 [신규] 사업보고서 본문 XML만 선택 (감사보고서 분리)
P0-신규

증상: v2 viewer 정합성 0/5. 추출된 V/VI는 연결감사보고서·감사보고서 안 "감사인"·"이사회 귀중"이 잘못 라벨링된 것. 사업보고서 본문은 검색조차 안 됐음.

근본 원인: Fix #2가 zip 3개 XML을 그냥 concat → 정규식이 가장 먼저 나오는 매칭(=감사보고서)을 잡아버림. 사업보고서 본문은 zip 안 세 번째 파일(20250311001085.xml, 5.78M자, DOCUMENT-NAME=사업보고서).

v3 접근:

  • zf.namelist()마다 <DOCUMENT-NAME ACODE="...">...</DOCUMENT-NAME>을 먼저 읽어 type 판별
  • type ∈ {"사업보고서"} 인 파일만 본문 corpus로 사용
  • type ∈ {"연결감사보고서", "감사보고서"} 는 별도로 보관 (참고용 — 다음 단계에서 노이즈 비교 데이터로 활용)
  • 여러 사업보고서 파일이 있으면 가장 큰 파일 선택 + 경고 로그
  • 사업보고서가 0개면 status='FAIL_NO_BUSINESS_REPORT'로 실패 처리 (위반금지 #1 준수)

검증 기준: Samsung 사업보고서 본문 텍스트 ≥ 1.5M자 + viewer 5개 sample ≥ 4/5 일치

1
II / IV / VII 한국어 헤딩 변형 보강
P0

증상: v2에서 II·IV·VII 매칭 실패. 단 P0-신규 적용 시 사업보고서 본문에서 다시 매칭 시도하므로 결과가 달라질 가능성 있음.

원인 가설: 한국어 표기 다양성 — II. · Ⅱ · 2. 외에 제2장, Part II, 2), 띄어쓰기/줄바꿈 변형. 또한 사업보고서 표지·목차에 키워드가 먼저 나와 잘못된 위치를 잡는 경우.

v3 접근:

  • 패턴 리스트 6~8개로 확대 (한·로마·아라비아 + 장/Part)
  • 각 매칭 후보를 모두 수집해 위치(pos) 정렬 → 본문 후보(목차 제외)는 pos > 임계값(예: 10,000자) 사용
  • 다음 헤딩이 없으면 "섹션 길이 cap" (예: 200,000자)으로 절단
  • 매칭 결과를 logs/section_match_v3.csv에 기록
2
strip_tags 무손실 보강 (lxml iter)
P0

증상: XML 6.93M → 텍스트 95.2K (압축률 1.4%). 사업보고서 본문 XML(5.78M)만 추출해도 압축률이 비정상이면 lxml 보강 필요.

v3 접근:

  • lxml.etree.fromstring(xml, recover=True) 후 root.itertext() 사용 — 태그 안 모든 텍스트 안전 수집
  • 실패 시 정규식 fallback (이중 안전망)
  • 각 단계 텍스트 길이 출력 (XML, strip, normalize) → 손실률 가시화

검증 기준: 사업보고서 XML 길이의 ≥ 20%가 텍스트로 남아야 함 (예: 5.78M → ≥ 1.15M)

v3 접근:

3️⃣ v3에서 추가할 "세분화 축" 5가지

A
multi-source 라벨링 보존
P1

zip 안 3개 XML을 버리지 않고 type별로 라벨링해서 모두 보존:

  • data/interim/<stock>_<year>_sections.json — primary (사업보고서 II/IV/VI)

정정공시 이력 추적 강화
P1

가이드 line 67-69 "정정공시가 있으면 어떤 rcept_no를 사용했는지 기록". v3에서:

  • last_reprt_at=Y로 최신만 가져오되 (현재 적용 중)

III·V·VII 헤딩 정밀 매칭 (II/IV/VI 경계용)
P1

  • 패턴 변형 6~8개 (한·로마·아라비아 + 띄어쓰기 변형 + 장/Part)
  • 매칭 후보를 pos 정렬해 본문 위치만 사용 (목차 위치 제외)
  • 회사별 매칭 결과를 logs/section_match_v3.csv에 기록 → Phase 2에서 분포 모니터링
D
표·그래프 텍스트 vs 본문 텍스트 분리
P2

  • lxml iter 시 tag == 'TABLE'인 노드는 section_tables에 별도 보관
  • 본문 텍스트 corpus와 표 텍스트 corpus를 분리해 passage 추출은 본문 중심 (선택적으로 표 포함 옵션)
  • 02 전처리에서 두 corpus의 ESG 표현 패턴 비교
E
회사·연도별 사업보고서 구조 다양성 대응
P2

Samsung 1건만으로는 일반화 불가 (v1·v2 보고서 §5.1에서 명시). Phase 2에서 발견되면 v4 가능성:

  • 업종별 II 섹션 길이 분포가 다름 (제조/금융/유통)
  • Phase 2 50건 결과를 회사별·업종별 heatmap으로 시각화 후 패턴 추출 → v4 필요 여부 판정
