## 1. 목적 (Why)

### 1.1 v3 실패 진단 → v4 존재 이유

v3는 가이드 line 18 의도(사업보고서 II/IV/VI)에 맞춰 사업보고서 본문 XML(5.78M자)을 정상 분리했으나, **헤딩 추출에서 치명 버그**:

- 정규식 매칭이 표지·요약·목차·본문·각주를 구분하지 못해 헤딩 위치가 뒤죽박죽
  - 실측: II=16,914 / III=5,197 / IV=290,091 / V=270,885 / VI=7,063 / VII=7,058
- 슬라이싱 `text[II:III]` = `text[16914:5197]` 이 **역방향**이라 II/IV/V/VI 모두 **0자**
- passage 0건 → viewer 검증 실행 불가

**근본 원인 (직접 lxml 검증):**
- DART XML은 **이미 구조화**돼 있음: `<SECTION-1>` 14개 = 사업보고서 I~XII + 표지·확인
- 각 SECTION-1 안 `<TITLE>` 노드에 `AASSOCNOTE="D-0-X-Y-Z"` 형식의 공식 hierarchical 식별자
- v3는 풍부한 마크업을 itertext로 평탄화 후 정규식으로 다시 찾으려 한 자기 발등 찍기

**dart-fss-text 라이브러리 발견:**
- 우리가 풀려는 문제(DART 사업보고서 텍스트 추출)를 위한 전용 라이브러리
- 핵심 접근: XML 파싱 + 정규식 + fuzzy matching + section_code 체계 (020000=II, 040000=IV, 060000=VI)
- v4는 이 패턴을 채택

본 v4의 목적: **lxml로 SECTION-1 14개 노드 직접 순회 + TITLE 텍스트 매칭 + AASSOCNOTE 보조**로 II/IV/VI을 정확히 추출하여 viewer ≥ 4/5 통과 후 Phase 2 진입.

### 1.2 분석 가설과의 연결

본 프로젝트 가설: **공시 ESG 언어 → KCGS 등급**. 가이드 line 18은 "사업보고서의 II, IV, VI 섹션에 담긴 ESG 관련 표현"을 target으로 명시. v4는 이 target을 정확히 추출하여 가설 검증의 입력 corpus를 만든다.

## 3. 방법 (What & How) — v3 → v4 핵심 변경

### 3.1 Fix #6 (신규) · lxml SECTION-1 직접 순회 (Step 6) — 🚨 v4 핵심

**v3 문제**: 정규식 평탄 텍스트 매칭이 목차·본문 구분 실패 → 위치 뒤죽박죽.

**v4 해결:**

```python
def extract_sections_v4(xml_text: str) -> tuple[dict, list]:
    parser = etree.XMLParser(recover=True, huge_tree=True)
    root = etree.fromstring(xml_text.encode('utf-8'), parser=parser)
    sec1_nodes = root.findall('.//SECTION-1')  # 14 노드

    sections = {}
    for idx, s1 in enumerate(sec1_nodes):
        title_el = s1.find('.//TITLE')
        title_text = (title_el.text or '').strip()
        aassoc = title_el.get('AASSOCNOTE', '')

        # 1) AASSOCNOTE 우선 (D-0-2-0-0 → II, 020000)
        label, section_code = parse_aassocnote(aassoc)

        # 2) TITLE 텍스트 매칭 (VI 등 AASSOCNOTE 빈 값 케이스)
        if not label:
            label = match_title_to_label(title_text)
            section_code = SECTION_CODE_MAP[label][0] if label else ''

        # 3) SECTION-1 노드 안 itertext (표 + 본문 평탄화)
        node_text = ' '.join(t.strip() for t in s1.itertext() if t.strip())
        sections[label] = {
            'section_code': section_code, 'section_title': title_text,
            'text': node_text, 'char_count': len(node_text), ...
        }
    return sections
```

**🔍 viewer 정합성 추가 점검 — 정정**

작성 초기에 사용자가 "원문 내용 그대로 가져간 것은 아니고 일부 내용이 생략되어 있다"고 지적했으나, 사용자 재확인 결과 **단어 누락은 없었으며 잘못 본 것으로 확인** (2026-05-16 사용자 정정). 즉 v4 추출 텍스트는 원문 사업보고서와 정합. 추가로 4가지 텍스트 추출 방법(strip+filter / no-filter / 공백 정규화 / `etree.tostring`)을 직접 비교한 결과 **±1% 이내 동등** → itertext 누락 의심 가설은 기각.

**II/IV/VI char_count 실측 — 목표가 아닌 실제 분량:**

작성 초기 v3·v4 로드맵에서 임의로 설정한 목표(II ≥ 100K, IV ≥ 30K)는 **근거 없는 추측이었음 (제 실수)**. Samsung 사업보고서 본문의 **실제 분량 계측 결과**:

| 섹션 | raw XML | strip 후 텍스트 | 본문(표 제외) | 표 텍스트 | 표 비중 |
|---|---|---|---|---|---|
| II 사업의 내용 | 142,834자 | **37,632자** ✅ | 26,473자 | 10,863자 | 29.1% |
| IV 이사의 경영진단 | (raw XML 추정) | **15,726자** ✅ | (분석 미실시) | (분석 미실시) | — |
| VI 이사회 등 회사의 기관 | (raw XML 추정) | **29,728자** ✅ | (분석 미실시) | (분석 미실시) | — |

→ **목표 미달이 아니라 실제 사업보고서 II/IV/VI의 본문 + 표 분량 자체가 그 정도**. Phase 2 50건에서 회사·업종별 분포가 도출되면 통계 기반 정상 범위 재설정 가능.
