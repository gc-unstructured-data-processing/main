## 3. 방법 (What & How) — v1 → v2 변경 4가지

### 3.1 Fix #1 · `find_project_root()` 헬퍼 (Step 1)

**v1 문제**:
```python
ROOT = Path('..').resolve().parent.parent  # cwd 의존
```
Jupyter cwd가 `notebooks/`가 아니면 ROOT가 잘못됨 → `.env` 인식 실패.

**v2 해결**:
```python
def find_project_root() -> Path:
    for candidate in [Path.cwd(), *Path.cwd().parents]:
        if (candidate / 'data' / 'company_master.csv').exists():
            return candidate
    raise FileNotFoundError(...)
ROOT = find_project_root()
```
anchor 파일(`data/company_master.csv`) 기준으로 cwd부터 상위 경로 탐색. 위치 무관 견고.

**근거**: 사용자 직접 수정 (2026-05-15) · 실무 ETL 표준 패턴.

**벤치마킹**: pytest `rootdir` 탐색 패턴 · pyproject.toml 기반 root 탐색.

### 3.2 Fix #2 · zip 안 모든 XML concat (Step 5) — 핵심 fix

**v1 문제** (실행 출력 증거):
```
📦 캐시에서 로드: 005930_2024_disclosure.zip (660.2 KB)
   📄 zip 안 파일 3개 — 첫 번째 사용: 20250311001085_00761.xml

📄 XML 길이: 623,804자
   앞 300자 미리보기:
   '<DOCUMENT-NAME ACODE="00761">연결감사보고서</DOCUMENT-NAME>...'
```

zip 안 3개 파일 중 **첫 번째가 "연결감사보고서"**. 사업보고서 본문(II/IV/VI 섹션 포함)은 다른 파일에 있음. v1은 첫 파일만 파싱하여 섹션 추출 0건.

**v2 해결**:
```python
def download_document_xml_v2(...):
    xml_files = []
    with zipfile.ZipFile(BytesIO(zip_bytes)) as zf:
        for name in zf.namelist():
            xml_bytes = zf.read(name)
            xml_text = xml_bytes.decode('utf-8', errors='ignore')
            xml_files.append((name, xml_text))
    return xml_files, zip_path

# concat
concat_xml = '\n\n'.join(text for _, text in xml_files)
sections = extract_sections_v2(concat_xml)
```
모든 XML 파일을 디코드 후 concat → 단일 큰 텍스트에서 섹션 헤딩 검색.

**근거**: v1 실패 진단 (zip 다중 파일 미처리) · 가이드 02 line 155 \"document.xml을 raw ZIP으로 저장\" (raw 보존은 지킴, 단 모든 파일 처리).

**벤치마킹**: 공개코드 dart-fss `parsers/disclosure.py`의 zip 안 multi-XML 처리 패턴.

### 3.4 Fix #4 · collection_log 컬럼 mismatch 자동 처리 (Step 9)

**v1 문제**:
```
ParserError: Expected 9 fields in line 3, saw 10
```
기존 log 컬럼 9개 + 새 함수 10개 (`viewer_url` 추가) → 읽기 실패.

**v2 해결**:
```python
EXPECTED_LOG_COLUMNS = [...10개...]

def append_log_v2(...):
    if log_path.exists():
        existing = pd.read_csv(log_path, nrows=0)
        if list(existing.columns) != EXPECTED_LOG_COLUMNS:
            # 백업 후 새 헤더로 재작성
            bak_path = log_path.with_suffix(f'.csv.bak_{...}')
            log_path.rename(bak_path)
            print(f'⚠️ log 컬럼 mismatch — 백업: {bak_path.name}')
    df_row.to_csv(log_path, mode='a', ...)
```

**근거**: v1 ParserError 진단 · 실무 ETL (스키마 변경 시 백업 + 재작성).

**벤치마킹**: 실무 데이터 파이프라인 (Snowflake / BigQuery 스키마 evolution 패턴).
