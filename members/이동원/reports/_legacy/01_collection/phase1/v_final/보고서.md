### 1.2 v1 → v_final 학습 로그

총 6번의 버전 발전을 통해 "단순한 수집"이 "가이드 의도 충실 구현"으로 성숙:

### 1.3 v_final의 차별점 (v5 → v_final)

v_final은 v5에 다음을 보강:
1. **Markdown 셀 상세화**: 각 Step에 Why(의도) / What(구현) / 벤치마킹 출처 / 가이드 line 매핑 명시
2. **Step 0 위반금지 사전 점검**: 8항목 + 가이드 line별 인용 + 본 노트북 적용 위치 매핑
3. **Step 11 self-check 강화**: 위반금지 + 가이드 04 채점 재현성 + 가이드 line 18 의도 충실도
4. **시각화 보강**: 14 SECTION-1 body/tables stacked bar + status 분포 + body/tables 차원 비교
5. **self-contained 100% 보장**: 외부 모듈 import 없이 단독 Run All 재현 가능 (가이드 04 §2-1 준수)

### 3.2 Step별 매핑 (가이드 line 153~158, 1~6단계)

#### Step 4 — stock → corp (가이드 line 153, 1단계)

`fetch_corp_code_map()`: corpCode.xml 1회 다운로드 → parquet 캐시 → 재호출 ❌ (idempotent).

#### Step 5 — corp → rcept + Fix #13 (가이드 line 154, 69, 2단계)

`find_rcept_no_v5()`: 차순위 fallback:
- 1순위: 사업보고서 (2024.12) — `pblntf_detail_ty=A001`
- 2순위: 반기보고서 (2024.06) — `pblntf_detail_ty=A002`
- 3순위: 분기보고서 (2024.09 / 2024.03) — `pblntf_detail_ty=A003`
- 모두 실패 → `FAIL_LIST_NO_REPORT` 명시적 raise (위반금지 #1)

정정공시 이력은 `last_reprt_at=N`으로 별도 수집 → `correction_log.csv`에 누적 (가이드 line 69).

#### Step 6 — zip 보존 + Fix #0 type 판별 (가이드 line 155, 3단계)

`download_document_xml_v5()`:
- zip 보존 (`data/raw/`, idempotent, 위반금지 #5)
- 각 XML의 `<DOCUMENT-NAME>` 메타 추출 (Fix #0)
- fallback_label에 따라 primary 선택 (PRIMARY_BIZ → 사업보고서 / FALLBACK_HALF → 반기보고서)
- 보조 보고서 → `save_aux_sources()` 별도 json (세분화 축 A)

#### Step 7 — Fix #6 + Fix #12 (가이드 line 156-157, 4-5단계) — 핵심

`extract_sections_v_final()`:
- lxml로 `<SECTION-1>` 14 노드 순회
- **1차 매칭**: `AASSOCNOTE` 속성 (`D-0-2-0-0` → II, 020000)
- **2차 매칭**: TITLE 텍스트 (VI 등 AASSOCNOTE 빈 값 케이스, `match_title_to_label()`)
- 각 노드 안에서 `itertext()` 3번 호출:
  - `section_text` = 전체 (body + tables)
  - `section_body` = TABLE 제거 후 (`deepcopy` + `parent.remove(tbl)`)
  - `section_tables` = TABLE 노드만 모음
- `section_match_v_final.csv`에 14 노드 매칭 method + table_ratio 누적

#### Step 8 — ESG passage (가이드 line 158, 6단계)

`extract_passages_v_final()`:
- source 옵션 (`'text'` / `'body'` / `'tables'`) 선택
- v_final 기본: `'body'` (서술 본문에서 ESG 표현 추출)
- 순수 Python `re`로 seed 매칭 (위반금지 #3 MCP 의존 ❌)
- 출력 컬럼: `section, section_code, source, dimensions, matched_terms, n_matches, sentence`

#### Step 9 — viewer 정합성 검증 (가이드 line 67, 94 + 위반금지 #3)

5개 sample (body 기준) 출력 → 사용자가 viewer URL을 직접 열어 확인. 판정 기준: ≥ 4/5 → Phase 2A 진입 가능.

#### Step 10 — collection_log + 시각화 (가이드 line 137-146, 170-172)

- `append_log_v_final()`: Fix #4 컬럼 mismatch 자동 백업 + Fix #5 status 11종 세분화
- 시각화: status 분포 + body vs tables 차원 비교

#### Step 11 — self-check (위반금지 8항목 + 가이드 04 재현성)

8항목 + 가이드 04 §2-1 self-contained 보장 확인.
