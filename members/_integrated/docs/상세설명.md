## §0. 프로젝트 한 줄 요약 + 필수 용어

### 한 줄 요약
> 한국 상장사 **127개 × 3개 회계연도(2022·2023·2024) = 381 firm-year**의 DART 사업보고서 텍스트에서 ESG 단어를 뽑아 숫자(feature)로 만들고, 그 숫자가 KCGS의 실제 ESG 등급과 **얼마나 연관**되는지 측정·검증·해석한다. **목표는 등급 맞히기가 아니라, 모든 선택을 데이터로 정당화하고 한계를 정직하게 적는 것.**

### 분석 전체를 관통하는 3대 원칙
1. **연관(association)만, 인과(causation) 아님** — "ESG 단어가 많은 회사가 등급도 높더라"까지만. "공시가 등급을 만들었다"는 주장 안 함.
2. **cheap-talk 경계** — 점수가 높은 게 *진짜 ESG를 잘해서*인지 *보고서가 길어서(말만 많아서)*인지 끝까지 구분. 이 분석의 가장 중요한 적(敵).
3. **모든 선택에 근거** — 분석기·임계값·파라미터를 고를 때마다 "왜 이 값인지"를 데이터로 보여줌(Decision Box, sweep, robustness).

### 필수 용어표 (모르면 설명이 막히는 것들)

| 용어 | 뜻 |
|---|---|
| **firm-year (기업-연도)** | "삼성전자 2024년" 같은 *기업1개+연도1개* 단위. 분석 기본 단위. 381개. |
| **DART** | 금융감독원 전자공시시스템. 사업보고서가 올라오는 곳. |
| **사업보고서 II/IV/VI** | 보고서의 장. II=사업의 내용, IV=경영진단(경영진 의견), VI=이사회 등 기관(지배구조). 로마숫자. |
| **KCGS / ESG 등급** | 한국ESG기준원이 매긴 외부 등급(D~A+). 우리가 비교하는 "정답지" 역할. |
| **E / S / G** | Environmental(환경)·Social(사회)·Governance(지배구조). |
| **seed 단어** | 출발점 ESG 핵심어 30개(E/S/G 각 10). 교수 제공. |
| **expanded dictionary** | seed에서 기계로 유사어를 넓혀 만든 확장 ESG 사전. |
| **token (토큰)** | 텍스트를 쪼갠 단어 조각. "토큰화"=쪼개는 것. |
| **TF-IDF** | 어떤 단어가 *이 문서에서 유독* 두드러지는 정도 점수. (§3에서 상세) |
| **cosine similarity** | 두 텍스트를 벡터로 바꿔 방향이 얼마나 닮았는지(0~1). |
| **feature** | 분석/회귀에 넣는 숫자 변수. |
| **ρ (rho, 스피어만 상관)** | 두 변수 *순위*가 같이 움직이는 정도(−1~+1). |
| **β (베타, 회귀계수)** | X가 1 늘 때 Y가 변하는 양·방향. |
| **p-value** | 결과가 우연일 확률(작을수록 유의). |
| **NaN** | Not a Number = 값이 비어 있음(결측). |
| **assert** | "이 조건이 참이어야 한다, 아니면 즉시 에러"라는 안전장치 코드. |
| **checkpoint(체크포인트)** | 이미 만든 파일이 있으면 다시 안 만들고 불러오는 패턴(시간 절약·재현성). |
| **Decision Box** | 노트북 안에서 "이 선택을 왜 했는지" 적어둔 마크다운 상자. |

> 노트북 구조 한눈에: **§0 셋업(셀0~3) → 1장 수집(셀4~20) → 2장 전처리(셀21~38) → 3장 feature(셀39~59) → 4장 validity(셀60~67) → 5장 회귀(셀68~76) → 6장 알파/섹션(셀77~98) → 7장 증거매트릭스(셀99~101) → 8장 결론(셀102)**. 시각화 6개는 각 해당 결과 뒤에 붙어 있음.

## 1장. 데이터 수집과 출처 검증 (셀 4~20)

목표: "올바른 firm-year의 올바른 보고서에서 텍스트를 가져왔다"를 **전수로 보증**. 분석 토대라 검증이 촘촘함.

### 셀 5 (CODE) — `1-1` 식별자 진단 + corp_code 매핑 (Decision Box ①②③)

- **[무엇]** company_master.csv를 읽고, 식별자를 점검하고, DART 조회에 필요한 `corp_code`를 직접 채운다.
- **[자세히 — 코드 흐름 순서대로]**
  1. `pd.read_csv(master_csv, dtype={"stock_code": str})` — CSV를 데이터프레임으로. `dtype=str`로 종목코드를 *문자열*로 읽음(숫자로 읽으면 앞의 0이 날아감).
  2. `cm["stock_code"].str.zfill(6)` — **Decision Box ①**. `zfill(6)`=zero-fill, 왼쪽을 0으로 채워 6자리 강제. `5930`→`005930`. 안 하면 표 병합 때 안 맞음. 바로 아래 `assert all(... len==6)`로 전행 6자리임을 강제 검증.
  3. **식별자 진단**: `nunique()`(고유값 개수)로 회사명 133개 ≠ 종목코드 127개 확인 → "이름으로 합치면 안 되고 stock_code×fiscal_year로"라는 결론의 근거.
  4. **timing 진단 (Decision Box ②)**: `(esg_year - fiscal_year).value_counts()` → 분포가 전부 0 = 두 컬럼이 381행 전부 동일. 그래서 `search_year = fiscal_year + 1`(보고서 검색용)만 따로 만들고, 등급은 같은 연도로 붙임.
  5. **corp_code 매핑 (Decision Box ③)**: CSV의 corp_code는 비어 있음(과제가 학생더러 찾으라고 일부러 비워둠). DART의 전체 상장사 매핑 파일 `corpCode.xml`을 **checkpoint 패턴**(`if os.path.exists`)으로 1회 다운로드→압축 해제→`ET.parse`(XML 파서)로 읽어 `stock_code→corp_code` 사전(`stock_to_corp`)을 만들고 `.map()`으로 붙임.
  6. **Sanity check**: 삼성전자가 `00126380`으로 잘 붙었는지 눈으로 확인. `META_INPUT_DF`라는 이름으로 저장(이후 모든 수집의 입력표).
- **[용어]** `ET`=ElementTree, 파이썬 기본 XML 파서. `.findall(".//list")`=XML에서 모든 `<list>` 태그 찾기. `.map(dict)`=각 값을 사전으로 치환.
- **[설명 포인트]** "corp_code가 없으면 DART 조회 자체가 불가 → 그래서 매핑이 1장 첫 작업. checkpoint로 매번 재다운로드 안 함."

### 셀 8 (CODE) — `1-2` 수집 함수 4종

- **[무엇]** DART에서 텍스트를 가져오는 과정을 **4개 함수**로 분리 정의.
- **[자세히 — 함수별]**
  1. **`find_business_report_v2(corp_code, fiscal_year, ...)`** — "어떤 보고서?" 찾기.
     - `list.json` API 호출. 파라미터: `bgn_de`/`end_de`=검색 시작/끝 날짜(begin/end date, `{search_year}0101`~`1231`), `pblntf_detail_ty="A001"`=공시상세유형 코드(사업보고서), `page_count`=한 번에 받을 개수.
     - **필터**: report_nm(보고서명)에 "사업보고서"가 있고 "반기·분기·연장·신고서"가 **없는** 것만. (1년 치 정규 보고서만 원함.)
     - **정정 우선순위**: 내부함수 `priority()`가 `[첨부정정]=2 > [기재정정]=1 > 원본=0`. `sort`로 우선순위·날짜 정렬 후 최신본 1개 선택. → 같은 보고서의 수정본이 여럿이면 가장 정정된 최신본 사용.
     - 반환: rcept_no(접수번호)·rcept_dt(접수일)·report_nm·후보수.
  2. **`download_document_xml(rcept_no, ...)`** — 원문 XML 받기.
     - `document.xml` API가 **ZIP(압축)** 으로 줌. `res.content[:2] != b"PK"` 체크: 모든 ZIP은 `PK`로 시작 — 서버가 에러(ZIP 아님)를 줬는지 확인하는 안전장치.
     - **본 XML 선택 (Decision Box ⑤)**: ZIP 안에 XML이 여러 개일 수 있어 ① 정확히 `{rcept_no}.xml` → ② 언더스코어(`_`) 없는 것 → ③ 가장 큰 파일 순.
     - **인코딩**: 한글 안 깨지게 utf-8→euc-kr→cp949 순 시도(`decode`). 인코딩=글자를 바이트로 저장하는 규칙.
     - **checkpoint**: ZIP 이미 받았으면 재다운로드 skip.
  3. **`extract_esg_sections(xml_text)`** — II·IV·VI 섹션만 추출.
     - **정규표현식(regex)** `ROMAN_PAT`: 줄 첫머리의 로마숫자(II. IV. VI.)만 "대분류 제목"으로 인식. `re.finditer`로 모든 `<TITLE>`을 찾아 그 중 로마숫자로 시작하는 것만 섹션 경계로 사용. (소제목까지 경계로 잡으면 섹션이 잘못 잘려 버그 → 대분류만 쓰도록 수정한 부분.)
     - `TARGET = {"II","IV","VI"}`만 남김. 각 섹션 = 이 제목부터 다음 로마제목 전까지.
     - `re.sub(r"<TABLE...>.*?</TABLE>", " ", ...)` — 재무표 등 표 블록 제거(ESG 텍스트 아님).
     - `<P>`(문단) 태그 안 텍스트만 모으고 `<[^>]+>` 패턴으로 잔여 태그 제거, `html.unescape`로 `&amp;`→`&` 복원, **10자 미만 조각은 버림**.
  4. **`collect_one_firm_year(row, ...)`** — 위 3개를 순서대로 실행하는 묶음.
     - 각 단계 실패 시 `{"status":"FAIL","reason":"보고서_미발견"/"ZIP오류"/"섹션_미추출"}` 반환 → **왜 실패했는지** 기록(가이드 요구 충족).
     - 성공 시 합본 텍스트 + 섹션별 글자 수 + **viewer_url**(사람이 원문 직접 보는 주소)까지 묶어 반환.
- **[설명 포인트]** "왜 4개로 쪼갰나?" → 단계마다 실패 지점·디버깅 단위가 달라서. "보고서 못 찾음"인지 "ZIP 깨짐"인지 "섹션 추출 실패"인지 분리 진단·재사용 가능. 이게 자주 받는 질문.

### 셀 16 (CODE) — `1-5` 품질 진단 + lineage 전수 검증
- **[무엇]** 4가지 점검: ①글자수 분포 ②섹션 0자 ③연도·섹션 분포 ④lineage(출처 계보).
- **[자세히]**
  - ① 평균 ≈34,773자, 최소 4,513 / 최대 189,606 → **42배 편차**(나중 cheap-talk 논의의 씨앗: 길이가 천차만별).
  - ② II·IV·VI 빈 섹션 0건.
  - ③ 섹션 비중 II 61.4% · IV 30.1% · VI 8.5%(VI=지배구조가 가장 짧음 → 6장에서 중요).
  - ④ **lineage 전수 검증**: rcept_no 중복 0건 / 정정공시 몇 건인지 기록 / report_nm의 대상기간 연도 vs fiscal_year 대조 → 불일치 **6건** = 비12월 결산법인(001720 3월·001080 6월) 자동 검출(버그 아닌 정상).
- **[용어]** lineage=데이터가 어디서 왔는지의 계보/이력.
- **[설명 포인트]** "단건(삼성)이 아니라 **381건 전수** 출처 점검 → 무결성을 통계가 아닌 *출처 수준*에서 보증."

### 셀 19 (CODE) — `1-6` 재무통제변수 수집 (가이드 [선택])
- **[무엇]** DART 재무 API로 firm-year별 재무비율 4종 계산(나중 회귀 통제용).
- **[자세히]**
  - `fnlttSinglAcntAll` API(단일회사 전체 재무제표)로 자산·부채·순이익·매출·영업이익 수집(연결 CFS 우선, 없으면 개별 OFS).

  - **가이드 원칙**: 못 찾은 항목은 **가짜 0 대신 NaN**. 금융지주 등은 "매출액" 대신 "영업수익"이라 매출 기반 비율이 정의 안 됨 → NaN.

- **[설명 포인트]** "분량(cheap-talk)뿐 아니라 *규모*까지 통제해 신호의 진짜 여부를 가리려는 준비."

## 2장. 전처리 — 텍스트를 깨끗한 단어로 (셀 21~38)

목표: 사업보고서 텍스트를 분석 가능한 **명사 토큰**으로 쪼개되, ESG 신호(특히 합성어)를 손상 없이 보존.

### 왜 한국어는 토큰화가 까다로운가
영어는 띄어쓰기로 단어가 갈리지만, 한국어는 조사·어미가 붙음("온실가스를", "감축하였다"). 그래서 **형태소 분석기**(morphological analyzer)로 의미 단위를 잘라야 함. 우리는 **명사(NNG=일반명사, NNP=고유명사)** 만 추출(ESG 신호는 주로 명사).

### 셀 22~23 (CODE+MD) — `2-1` 분석기 선택 (Kiwi vs Okt)
- **[무엇]** 두 형태소 분석기 **Kiwi**와 **Okt**를 seed 보존·복합명사·속도로 비교.
- **[자세히]** `extract_nouns_kiwi(text, analyzer)`와 `extract_nouns_okt(text)`로 같은 문장을 토큰화해 비교. "보존"=`넷제로`가 `넷`+`제로`로 쪼개지지 않고 한 단어로 유지. 속도도 30개 샘플로 측정(`time.time()`).
- **[결과]** Kiwi가 seed 보존 우수 → 채택. (Decision Box ⑦, 셀 29.)
- **[용어]** **kiwi_base**(기본 Kiwi) vs **kiwi_user**(사용자 사전 등록된 Kiwi) — 둘을 비교해 사전 효과도 확인.

### 셀 24~26 (MD+CODE+MD) — `2-1B` (HF) subword 토크나이저 비교 ★HF 추가분
- **[무엇]** 허깅페이스(HF)의 `klue/bert-base` **subword 토크나이저**와 Kiwi를 비교.
- **[자세히]**
  - **HF(HuggingFace)**=AI 모델 공유 플랫폼/라이브러리.
  - **subword(서브워드)**=단어를 의미 조각으로 더 잘게 나눔. `넷제로`→`넷`,`##제`,`##로`. `##`=앞 조각에 이어붙는다는 표시(WordPiece 방식).
  - `hf_preserves(term)` 함수: subword가 단어를 한 조각으로 보존하면 True(=`len(pieces)==1 and not ##`).
- **[결과]** subword는 ESG 합성어를 자주 분할 → seed 보존 **16/30(53%)**. Kiwi 사용자사전 **28/30(93%)**.
- **[설명 포인트]** "subword가 무조건 나쁜 게 아니라, *사전 기반 ESG seed 점수* 측정엔 합성어 보존이 핵심이라 Kiwi가 맞다." 단 "단일 조각=보존"이라는 보수적 기준임도 명시.

### 셀 27~28 (MD+CODE) — 📊 [시각화] 형태소 분석기 비교 ★시각화 추가분
- **[무엇]** Kiwi 28/30 vs HF 16/30, 차원별(E/S/G) 보존 막대그래프.
- **[자세히]** 왼쪽=전체 보존율 막대(28 vs 16), 오른쪽=차원별 그룹 막대(파랑=Kiwi, 회색=HF). `outputs/viz_analyzer_compare.png`로 저장.
- **[설명 포인트]** "비교는 수치보다 그림이 빠르다 — Kiwi 막대가 항상 위. 특히 S·G에서 격차 큼."

### 셀 31~32 (CODE+MD) — `2-2` Kiwi 사용자 사전 + 불용어 구축
- **[무엇]** seed 30개를 Kiwi에 등록하고, 불용어(분석에서 뺄 단어) 목록을 만든다.
- **[자세히]**
  - `kiwi.add_user_word(term, "NNP", score=50.0)` — seed 30개를 "고유명사다, 점수 50으로 강하게 인식"이라고 Kiwi에 등록. 이래야 `재생에너지`를 한 단어로 봄. **score=50.0**=인식 우선순위(높을수록 안 쪼갬).
  - `extract_nouns_kiwi` 함수: 텍스트→2자 이상 명사 리스트. **이후 모든 단계가 이 함수 재사용.**
  - **seed 보존 검증**: 까다로운 문장 8개로 테스트→`assert` 8/8 통과 강제.
  - **불용어 3종**: ①기본 불용어(의미 없는 일반 경영어), ②**회사명 토큰**(회사명 133개를 Kiwi로 쪼갠 명사 → 불용어화. 회사 이름이 신호 오염시키는 것 방지), ③보일러플레이트(공시 정형어).
  - **★seed 강제 보호**: 3종 합친 뒤 seed 30개는 불용어에서 무조건 제외. (예: `에너지`가 어느 회사명에서 쪼개져 불용어에 들어가도 seed라 살림.)
- **[용어]** 불용어(stopword)=의미 없거나 너무 흔해 분석에서 빼는 단어.

### 셀 34~35 (CODE+MD) — `2-3` 전체 corpus 토큰화
- **[무엇]** 381개 텍스트 전부 토큰화 → `TOKEN_DICT`(firm-year별 단어 리스트).
- **[자세히]** checkpoint(`tokens_kiwi.json`)로 재실행 시 10~20분 절약. 진단: firm-year별 토큰 수, seed 빈도(희소 seed 발견), 고빈도 단어 Top 30.
- **[용어]** corpus(코퍼스)=분석 대상 텍스트 전체.

### 셀 37~38 (CODE+MD) — `2-4` 전처리 검증 마무리 ★추가분
- **[무엇]** 전처리가 ESG 신호를 안 죽였는지 2가지 사각지대 점검.
- **[자세히]**
  - (A) `넷제로`(7건)·`부패방지`(5건)가 실제 문서에서 단일 토큰으로 **완전 보존**(원문 등장수=토큰 보존수).

## 3장. Feature 생성 — 텍스트를 숫자로 (셀 39~59) ★방법론의 심장

목표: firm-year마다 E·S·G "ESG 표현 강도" 숫자 만들기. 세 방식: seed TF-IDF / expanded TF-IDF / 기준문장 cosine.

### TF-IDF 완전 이해 (가장 많이 받는 질문)
- **TF (Term Frequency, 단어빈도)**: 이 문서에서 그 단어가 몇 번?
- **IDF (Inverse Document Frequency, 역문서빈도)**: 그 단어가 전체 문서 중 몇 개에 나오나의 *역수*. **모든 문서에 다 나오는 흔한 단어는 IDF가 낮아 점수↓**, 특정 문서에만 나오면 점수↑.
- TF×IDF = "이 문서에서 *유독* 두드러지는 단어"에 고점. ESG 단어가 특정 firm-year에 두드러지면 그 점수↑.
- **코드 파라미터 (`TfidfVectorizer`)**:
  - `min_df=5`: 5개 미만 문서에만 나오는 희귀어 제외(노이즈 컷).
  - `max_df=0.80`: 80% 초과 문서에 나오는 너무 흔한 단어 제외(예: 모든 보고서의 `이사회`).
  - `sublinear_tf=True`: 빈도에 로그 적용(10번이 1번의 10배가 아니라 완만하게).
  - `tokenizer=lambda x: x.split(), token_pattern=None`: 이미 토큰화된 걸 공백으로만 자르라는 뜻(Kiwi 결과를 그대로 씀).

### 셀 40~41 (CODE+MD) — `3-1` seed TF-IDF 점수
- **[무엇]** seed 30개로 firm-year별 E/S/G 점수 생성.
- **[자세히]** max_df=0.80 때문에 G seed 7개(`이사회`·`사외이사`·`주주` 등 100% 등장 의무공시어)가 어휘에서 제외됨 → "G는 seed로 측정이 어렵다"는 단서.

### 셀 42~44 (MD+CODE+MD) — `3-1 보강` max_df robustness sweep ★추가분 (강력)
- **[무엇]** "max_df=0.80을 골라서 G가 약한 거 아냐?"라는 자의성 의심을 검증.
- **[자세히]** max_df를 0.80→1.0으로 **sweep(여러 값 훑기)** 하며 seed_G↔g_grade ρ 측정. 결과를 `sweep` 데이터프레임에 저장.

| max_df | seed_G ↔ g_grade ρ |
|---|---|
| 0.80 | **0.271** |
| 0.95 | 0.304 |
| 0.99 | 0.108 |
| 1.00 | **−0.162** |

- **[해석]** 보편어를 넣을수록 신호 붕괴, 1.0에선 **부호 반전**(음수). 즉 `이사회`·`주주`는 변별력 없을 뿐 아니라 많이 쓸수록 등급 낮은 **boilerplate(상투어)**.
- **[결론]** max_df=0.80은 자의가 아니라 **G 신호 보존에 필수**. "seed_G 측정 불가" → "약한 양의 신호(ρ=0.271)"로 정정.
- **[용어]** sweep=파라미터를 여러 값으로 바꿔가며 결과 변화를 보는 것. robustness=결론이 설정 바꿔도 견고한지.

### 셀 45~46 (MD+CODE) — 📊 [시각화] max_df sweep ★시각화 추가분 (선택 근거)
- **[무엇]** ρ가 0.271→−0.162로 떨어지는 선그래프. 채택점(0.80) 빨간 원으로 강조, 음수 구간 빨강 음영.
- **[설명 포인트]** "선이 우하향하다 0 아래로 꺾이는 게 한눈에 보임 → '보편어 넣으면 신호가 죽고 뒤집힌다'를 그림으로 증명. max_df=0.80 선택의 시각적 근거."

### 셀 47~49 (MD+CODE+MD) — `3-2` FastText 학습 + θ Sweep
- **[무엇]** corpus로 단어 임베딩(FastText)을 학습해 seed 유사어를 찾고, 임계값 θ를 sweep.
- **[자세히]**
  - **FastText**=단어를 의미 비슷한 것끼리 가까운 좌표(벡터)에 놓는 **단어 임베딩** 모델. 우리 corpus로 직접 학습.
  - 파라미터: `sg=1`(skip-gram 방식), `vector_size=100`(단어→100차원 좌표), `window=5`(앞뒤 5단어 문맥), `epochs=10`(데이터 10회 반복 학습).
  - **θ(theta) Sweep**: 유사어로 인정할 **cosine 유사도 기준선**을 0.55~0.75로 바꿔가며, 각 θ에서 cosine **상위 100단어**를 훑어 후보 수·잡음 비율을 표로(가이드 명시 요건). θ↓ = 후보↑ 잡음↑.
  - `is_noise()`: 숫자포함·1글자·영문만 등을 잡음으로 자동 표시.
- **[결과]** θ=0.65 채택(후보·잡음 균형). Decision Box ⑫(셀 50).

### 셀 52~53 (CODE+MD) — `3-3` Expanded Dictionary 큐레이션
- **[무엇]** θ=0.65 후보를 자동 필터 + 사람이 직접 검토해 확장 사전 확정.
- **[자세히]** 후보 660개(중복 포함) → 자동필터(2자 미만/영문숫자/불용어/차원중복 제거) 475개 → **수동 검토 기각** 42개 → **433개 채택**. `REJECT` 목록은 사람이 버린 것(대부분 이사 **인명**, 지명·기관명, 형태소 오분리, 시사 노이즈).
- **[검토 범위 표]** 기각률 E 9.8% · S 40.7% · G 5.8%. (G는 후보 많아도 진짜 거버넌스어라 기각 적고, S는 노이즈 많아 기각률 최고 → S 신호가 본질적으로 약함을 재확인.)
- **[설명 포인트]** "FastText가 준 걸 그대로 안 쓰고 **사람이 전수 검토**해 걸러냄 = 가이드 핵심 요구."

### 셀 55~56 (CODE+MD) — `3-4` Expanded Score + 기준문장 Cosine + 다중공선성
- **[무엇]** 확장 사전으로 점수 만들고, 기준문장 cosine(보조)도 만들고, feature 간 겹침을 진단.
- **[자세히]**
  - **expanded score**: 433개로 firm-year별 E/S/G TF-IDF 점수 → `PANEL_DF`(분석용 표).
  - **기준문장 cosine(ref_cosine)**: E/S/G 대표 문장(`ref_sentences`)과 각 firm-year의 TF-IDF cosine. 평균 0.016~0.024로 매우 낮음(거의 직교) → 약한 baseline.
  - **다중공선성(multicollinearity)**: feature끼리 너무 비슷하면 회귀가 불안정. 그래서 seed/expanded/cosine을 한 모델에 같이 안 넣고 **따로** 돌리기로.
- **[용어]** 직교(orthogonal)=상관 0에 가까움(거의 안 겹침).

### 셀 58~59 (CODE+MD) — `3-5` 상위/하위 문장 직접 읽기
- **[무엇]** 점수 높은/낮은 firm-year의 실제 문장을 눈으로 읽어 feature가 ESG 내용을 잡는지 확인(가이드 요구).

## 4장. Validity 검증 — 회귀 전에 "연관이 있긴 한가" (셀 60~67)

목표: 회귀 들어가기 전에 각 feature가 등급과 통계적으로 연관되는지 순위상관·집단비교로 먼저 확인.

### 핵심 용어
- **등급 숫자화**: `GRADE_MAP = {S:6, A+:5, A:4, B+:3, B:2, C:1, D:0}`. 회귀엔 숫자가 필요.
- **Spearman 순위상관(ρ)**: 값이 아니라 *순위*가 같이 움직이는지. 등급이 서열변수라 적절.
- **Mann-Whitney U(MWU)**: 두 집단(A이상 vs B+이하) 분포 차이 검정. 평균 아닌 순위 비교(정규분포 가정 불필요).
- **bootstrap CI**: 데이터를 무작위 재추출 여러 번 → 통계치 흔들림 범위 추정.
- **효과크기 vs 유의성**: p값(우연인가)과 별개로 *얼마나* 큰 차이인지.

### 셀 61~62 (CODE+MD) — `4` Validity (Spearman 40개 + MWU + FDR)
- **[무엇]** 10 feature × 4 등급 = 40개 상관 + 집단 비교 + 다중비교 보정.
- **[자세히]**
  - **핵심 결과**: **n_tokens(분량) ρ=0.663으로 최강** — 어떤 ESG feature보다 강함. → cheap-talk 경고 출발점. expanded_E↔e 0.451, expanded_G↔g 0.426.
  - **MWU**: A이상(138) vs B+이하(243), n_tokens 효과크기 r=0.649(A이상 평균 토큰이 B+이하의 약 2.1배).
  - **FDR 보정 (`multipletests`)**: 40번 검정하면 우연히 "유의" 나오는 게 생김(다중비교 문제). **FDR(False Discovery Rate, 거짓발견율)** 로 보정 → 보정 후도 40/40 유의. 단 "유의 ≠ 효과 큼" 강조.
- **[설명 포인트]** "40번 검정의 함정을 FDR로 막음. 그리고 가장 큰 연관은 ESG 내용이 아니라 **분량**이더라."

### 셀 63~65 (MD+CODE+MD) — `4-1B` (HF) Dense Embedding Cosine ★HF 추가분 (정직한 반증)
- **[무엇]** 단어겹침이 아닌 *의미* 임베딩으로 cosine을 재고 TF-IDF와 비교.
- **[자세히]**
  - **dense embedding(밀집 임베딩)**: 의미를 768차원 벡터로. `ko-sroberta-multitask`(한국어 문장 임베딩 모델, HF)로 계산. "dense(밀집)"=0이 거의 없는 빽빽한 실수벡터(반대=TF-IDF 같은 sparse 희소벡터).
  - 방법: 기준문장 임베딩과 각 firm-year 문장들의 의미 유사도 중 **상위 5개 평균**.
- **[결과 — 반증]**

| 차원 | dense ρ | TF-IDF cosine ρ |
|---|---|---|
| E | +0.229 | **+0.367** |
| S | −0.144 | **+0.276** |
| G | −0.031 (무의미) | **+0.290** |

- **[해석]** "최신 의미 임베딩이 항상 낫다"는 통념과 달리, **이 과제(짧은 기준문장 1개 vs 긴 문서)에선 단어 기반이 더 유효**. 이유: 상위-k 평균이 다양한 서술을 한 점으로 압축(변별력↓), 일반도메인 모델이라 공시체 미세차이 포착 실패.
- **[위치 주의]** 이름은 "3장 dense 확장"이지만 등급(ANALYSIS_DF)이 필요해 **4장 뒤에 배치**(코드 의존성).
- **[설명 포인트]** "안 통한 결과를 숨기지 않고 *왜 안 통했나*까지 적은 게 오히려 가이드 정신(이유·한계)에 부합. 단어 baseline의 위상을 역으로 강화."

### 셀 66~67 (MD+CODE) — 📊 [시각화] dense vs TF-IDF ★시각화 추가분 (비교)
- **[무엇]** E/S/G별 dense ρ와 TF-IDF ρ를 나란히 막대.
- **[설명 포인트]** "세 차원 모두 파랑(TF-IDF)이 회색(dense)보다 높음 — 반증이 한눈에. S·G는 dense가 0/음수."

## 5장. 회귀 분석 — 분량을 통제해도 신호가 남는가 (셀 68~76)

### 📖 회귀분석 읽는 법 (팀원이 꼭 이해할 부분)
이 장은 "ESG 단어 점수↑ → 등급↑인가"를 보되, **"그게 단지 보고서가 길어서(cheap-talk)는 아닌가"** 를 가리려고 모든 모형에 분량(`log_n_tokens`)을 함께 넣어 분량 효과를 *빼고* 본다.
- **β(계수)**: 다른 변수 고정 시, feature 1↑당 등급 점수 변화량. 양수면 "점수↑→등급↑".
- **p<0.05**: 우연일 가능성 낮음(유의). *유의≠효과 큼*.
- **왜 3개 모형**: 등급은 서열변수(간격 동일 보장 없음)라 한 모형만 안 믿고 셋으로 교차검증.
  - **OLS**(최소제곱): 등급을 연속숫자로(간격 동일 가정). 가장 단순한 baseline.
  - **Ordered Logit**(순서형): 순서만 사용(간격 가정 없음). 계수 해석 까다로워 *방향* 위주.
  - **Binary Logit**(이항): "A이상이냐"(0/1). 해석 쉬운 대신 정보 일부 버림. **OR(승산비)** 로 해석.
- **M1 vs M2**: M1=분량만 통제, **M2=재무(규모·수익성·레버리지)까지 통제**. 살아남으면 진짜 신호, 사라지면 교란이었던 것.
- **log 변환**: 분량처럼 편차 큰 값(42배)은 로그로 분포를 완만하게.

### 셀 69~70 (CODE+MD) — `5` 회귀 3종 (M1)
- **[무엇]** seed/expanded/cosine × OLS/Ordered/Binary, 모두 `+log_n_tokens`.
- **[핵심 결과 (expanded, OLS)]**
  - **expanded_G: β=3.174, p<0.001** ★ — 분량 통제 후도 강하게 유의(독립 신호).
  - expanded_E: β=0.432, p=0.025 — 약하지만 유의.
  - expanded_S: β=−0.695, p=0.302 — **비유의**(분량 대리지표).
  - log_n_tokens: β=1.297, p<0.001 — 모든 모형에서 압도적. R²=0.476.
- **[변수 구조]** 결과는 `ols_res`(딕셔너리)에 feature_set별 회귀결과 저장 → 이후 시각화·M2가 재사용.

### 셀 71~73 (MD+CODE+MD) — `5-2` 모형 진단
- **[무엇]** ordered/binary 모형의 신뢰성 점검.
- **[자세히]**
  - **비례오즈 가정(proportional odds)**: ordered logit이 "모든 등급 경계에서 효과 동일"이라 가정 — cutoff별 계수로 확인. E·G·분량은 방향 일관(OK), **S는 부호 뒤집힘(가정 위반)** → ordered는 S의 *방향만* 읽기.
  - **seed_G 준완전분리(quasi-separation)**: binary에서 seed_G의 OR≈9.8e6(980만)로 비정상. 0값 비율이 A이상 57.2% vs B+이하 83.1%로 갈려 추정 폭발 → **해석 제외**.
- **[용어]** separation=한 변수가 결과를 거의 완벽히 가르면 계수가 무한대로 발산하는 현상.
- **[설명 포인트]** "계수가 말이 안 되게 크면 의심하고 진단 → 통계적 방어."

### 셀 74 (MD) — `M2` 재무통제 결과 (가이드 [선택])
- **[무엇]** M1에 재무(log_assets·roa·leverage) 추가. 재무 3변수 다 있는 **344 firm-year**(결측 37 제외, 가짜 0 안 씀).

| feature(expanded) | M1 β | M2 β | 판정 |
|---|---|---|---|
| expanded_G | +3.174 | **+1.955** (p<.001) | ★ 견고 |
| expanded_E | +0.432 | +0.172 (p=.396) | 유의성 소멸 |
| expanded_S | −0.695 | −0.070 (p=.918) | 비유의 |
| log_n_tokens | +1.297 | +0.718 (p<.001) | 절반↓이나 견고 |

- **[해석]** **E는 상당 부분 규모 교란**이었음(재무 통제 시 사라짐). **G는 규모·수익성·레버리지 통제 후도 생존**(진짜 거버넌스 신호). 분량도 단순 규모 아님(절반 줄어도 유의). R² 0.476→0.551.

### 셀 75~76 (MD+CODE) — 📊 [시각화] 회귀 M1→M2 ★시각화 추가분 (비교)
- **[무엇]** **dumbbell(아령) 그래프**: 각 feature의 M1 점(회색)과 M2 점을 선으로 연결, M2가 유의면 파랑·소멸이면 빨강.
- **[자세히]** `ols_res`와 `m2_res`에서 계수를 뽑아 그림. G는 파랑(견고), E는 빨강(소멸)으로 즉시 구분.
- **[설명 포인트]** "재무통제 후 살아남는 신호가 G뿐임을 점의 색과 이동으로 한눈에."

## 6장. 자체 딥 알파 — ESG 신호가 어느 섹션에 있나 (셀 77~98)

목표(가이드 "알파"=팀 자체 추가검증): 분량 통제 후 남는 신호가 II·IV·VI 중 **어디서** 오는지. 핵심은 섹션 *글자수*가 아니라 **섹션별 ESG 어휘 강도**.

### 셀 78~79 (CODE+MD) — `6-1` 섹션 텍스트 복원 + 점수
- **[무엇]** 합본 텍스트를 섹션별 글자수로 잘라 II·IV·VI 복원 → 섹션별 9개 점수(II_E…VI_G).
- **[자세히]** `(total_chars − Σsection_chars)`가 거의 모든 firm-year에서 일정함을 `assert`로 확인(구분자 길이 일정 → 글자 위치로 정확히 슬라이스 가능). `slice_sections()`로 자른 뒤 섹션별 재토큰화→TF-IDF→expanded 사전 매칭. 결과는 `sec_df`(컬럼 II_E…VI_G)와 `SECTION_SCORES`.
- **[관찰]** 이미 G가 VI에 집중 보임.

### 셀 81~82 (CODE+MD) — `6-2` 국소화 행렬
- **[무엇]** 각 섹션 점수와 *해당 차원* 등급의 ρ를 3×3 행렬(`loc` 딕셔너리)로.
- **[핵심]** **VI_G ↔ g_grade ρ=0.526** > 전체 문서 0.426 → 거버넌스를 *그게 공시되는 섹션(VI)* 에서 재면 더 선명(**sharpening**). E는 II+IV 분산, S는 국소화 실패.
- **[설명 포인트]** "G 신호는 흩어진 게 아니라 VI에 모여 있고 거기서 재면 더 또렷."

### 셀 83~84 (MD+CODE) — 📊 [시각화] 국소화 행렬 히트맵 ★시각화 추가분 (비교)
- **[무엇]** 섹션×차원 ρ를 **히트맵**(색 진하기로 값 표현). 빨강=양, 파랑=음(RdBu_r). VI_G·II_E 칸을 검은 테두리로 강조, p<.05는 `*`.
- **[설명 포인트]** "VI_G 칸이 가장 진한 빨강 — 대각선(자기 섹션)에 신호가 모이는 게 색으로 즉시 보임."

### 셀 85~87 (MD+CODE+MD) — `6-3` 섹션-길이 통제 회귀
- **[무엇]** 각 섹션 점수를 *그 섹션 글자수+전체 분량*으로 통제: "내용인가 분량인가".
- **[결과]** **VI_G(β=1.738)·IV_G(β=1.969) 생존**(★), II_G 흡수(boilerplate). **II_E 생존, IV_E 흡수.** → cheap-talk이 차원·섹션마다 다른 지형.

### 셀 88~90 (MD+CODE+MD) — `6-4` 정성 확인 (직독)
- **[무엇]** VI_G 상·하위 firm-year 직접 읽기.
- **[결과]** 상위=독립이사 의장·구체 거버넌스, 하위=CEO 겸직·최소 서술. II_E 상위는 에너지/환경 사업 → **섹터 교란**(에너지 기업이 환경어 많이 씀) 정직하게 지적.

### 셀 91~93 (MD+CODE+MD) — `6-5` 업종·연도 FE robustness
- **[무엇]** 업종·연도 고정효과(FE)를 넣어 업종/연도 공통효과를 빼고 봄.
- **[자세히]** **FE(Fixed Effects, 고정효과)**=업종·연도별 더미변수. **더미(dummy)**=범주를 0/1로 표현. `get_dummies(..., drop_first=True)`로 기준 범주 하나 빼서 다중공선성 회피. 업종은 firm-year 5개 이상만 살리고 나머지 "기타".
- **[결과]** VI_G·IV_G·II_E 전부 견고. 특히 **II_E는 강화(0.592→0.723)** — 섹터 교란 통제 후도 환경 신호 생존.

### 셀 94~96 (MD+CODE+MD) — `6-6` (HF) 임베딩 E/S/G 분류 ★HF 추가분
- **[무엇]** 6장 국소화가 *사전 매칭* 산물이 아닌지, 사전 없이 의미로 분류해 교차검증.
- **[자세히]**
  - 방법: `ko-sroberta`로 각 섹션 문장을 E/S/G/무관 기준문장과 cosine **최근접 분류**(argmax). (원래 NLI 제로샷을 쓰려 했으나 그 환경에 SentencePiece 라이브러리가 없어 로드 불가 → 이미 작동하는 임베딩 방식으로 대체. 목적 동일.)
  - **argmax**=가장 큰 값의 위치(가장 가까운 라벨). **NLI/제로샷**=학습 없이 라벨 해당 여부를 추론하는 방식.
  - 60 firm-year 층화표본 × 섹션당 12문장 상한(무거워서 제한).
- **[결과]** **VI 문장의 97.9%가 G로 분류** → G→VI 국소화가 사전 비의존으로 재현(robustness 성공). E·S 약함 → 본선 일치.
- **[설명 포인트]** "측정 방식을 사전→의미 임베딩으로 바꿔도 G→VI가 그대로 = 결론이 방법에 안 흔들림."

### 셀 97~98 (MD+CODE) — 📊 [시각화] 6-6 섹션 분류 ★시각화 추가분 (비교)
- **[무엇]** II/IV/VI별 E/S/G 문장 비율 **누적막대**. VI의 G(0.979)를 화살표로 강조.
- **[설명 포인트]** "VI 막대가 거의 전부 파랑(G) — 사전 기반 6-1·6-2와 같은 그림."

## 7장. 증거 종합 (셀 99~101)

### 셀 100~101 (CODE+MD) — Cheap-talk + 섹션 국소화 Evidence Matrix
- **[무엇]** 모든 증거를 한 표로 묶어 5범주 정리.
- **[자세히]**
  1. **분량 압도**: n_tokens↔esg ρ=0.663(최강), MWU 효과크기 0.649.

## 8장. 결론 (셀 102)

### 셀 102 (MD) — 종합 결론 + 한계 + HF 종합(8-3)
- **[8-1 핵심 답변]** 공시 언어와 ESG 등급엔 연관이 있으나 **가장 강한 건 ESG 내용이 아니라 분량(cheap-talk)**. 그래도 분량·재무 통제 시 **G에 독립 신호**가 남고, 그 신호는 **VI 섹션에 국소화되어 거기서 잴 때 가장 선명(sharpening)**. **E**는 부분 신호이나 규모 통제 시 약화, **S**는 사업보고서로 안정 측정 어려움.
- **[8-2 한계]** ①381행은 수업용 pilot(전체 대표 아님) ②공시 표현 ≠ 실제 성과 ③**가이드 정의(esg_year=fiscal_year+1) vs CSV(=fiscal_year) 불일치** → timing 한 해 어긋났을 가능성(연관 해석엔 제한적, 인과·예측 불가) ④재무 4비율 중 매출기반 2개 결측 많아 미사용 ⑤업종 FE 4그룹 단순화 ⑥**전부 연관, 인과 아님.**
- **[8-3 HF 종합]** HF는 새 결론이 아니라 *교차검증*: (a) **G 견고함**을 6-6이 사전 비의존으로 재현, (b) dense 실험은 단어 기반 타당성을 *역으로* 뒷받침(반증), (c) S 빈약 재확인. → HF는 본선을 **대체 아닌 지지·한정**.

## 부록 B. 자주 헷갈리는 영어·약어

- **OLS** = Ordinary Least Squares(최소제곱 회귀) / **OR** = Odds Ratio(승산비) / **FE** = Fixed Effects(고정효과)
- **TF-IDF** = Term Frequency–Inverse Document Frequency / **FDR** = False Discovery Rate(거짓발견율)
- **NLI** = Natural Language Inference(자연어 추론) / **SBERT** = Sentence-BERT(문장 임베딩 모델)
- **HF** = HuggingFace / **MWU** = Mann-Whitney U / **ρ** = Spearman rho(순위상관)
- **dense vs sparse** = 밀집(빽빽한 실수벡터) vs 희소(대부분 0) / **subword** = 단어를 더 잘게 쪼갠 조각
- **firm-year** = 기업-연도 / **cheap-talk** = 말만 많은 것(분량 부풀리기) / **boilerplate** = 상투적 정형 문구
- **sweep** = 파라미터 여러 값 훑기 / **robustness** = 결론이 설정 바꿔도 견고함 / **lineage** = 데이터 출처 계보
- **sharpening** = (국소화로) 신호가 더 선명해짐 / **confounder** = 교란변수 / **separation** = (회귀) 완전분리
