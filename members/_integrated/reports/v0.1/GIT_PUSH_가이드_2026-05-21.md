# GitHub 푸시 가이드 — 멤버별 branch → PR → auto merge (양쪽 레포)

> 작성: 2026-05-21 · 대상: 이동원(레포 솔로 관리) · 본인 PC(Git Bash/PowerShell)에서 실행
> **전제**: 로컬 정리 완료 상태(멤버 파일 배치 + 이동원 폴더 `integrated/v1` 메인화 + `_legacy/` 이력 보존).
> Cowork 샌드박스는 git push 인증·삭제가 막혀 직접 실행 불가 → **아래 명령을 본인 PC에서 실행**하세요.

## 0. remote 확인 (이미 설정됨)

```bash
cd <레포 루트>   # unstructured-data-processing-final-project
git remote -v
# origin → github.com/mygithub05253/unstructured-data-processing-final-project (개인)
# team   → github.com/gc-unstructured-data-processing/main (협업)
```

`gh`(GitHub CLI)가 있으면 PR·merge가 한 줄로 됩니다. 없으면 웹에서 PR 생성/merge (각 단계에 웹 방법 병기). 설치: https://cli.github.com → `gh auth login`.

---

## ⚠️ 시작 전 — 현재 변경 백업 + main 정렬

현재 작업 브랜치가 `feature/02-preprocessing-v1`이고 미커밋 변경이 많습니다. 안전하게 stash로 보관 후 main에서 시작합니다.

```bash
git stash push -u -m "wip-0521"        # 모든 변경(미추적 -u 포함) 임시 보관
git checkout main
git pull origin main                    # 개인 main 최신화
git pull team   main                    # 협업 main 최신화 (충돌 시 해결)
```

> 이후 각 멤버 branch에서 `git checkout stash@{0} -- <경로>`로 **필요한 경로만** 꺼내 commit합니다. 한 stash에서 여러 branch로 분배하는 방식입니다.

## 1. 멤버별 branch → commit → push → PR → merge

아래는 **신지영** 예시. 김혜성·김지우·이동원·대시보드도 동일 패턴(경로·메시지만 교체).

```bash
# (1) main 기반 새 branch
git checkout -b feat/member-shinjiyoung main

# (2) stash에서 신지영 경로만 꺼내기
git checkout stash@{0} -- members/신지영/

# (3) commit
git add members/신지영/
git commit -m "feat(신지영): 0519 전처리 노트북·HTML + README"

# (4) 양쪽 remote에 push
git push -u origin feat/member-shinjiyoung
git push    team   feat/member-shinjiyoung

# (5) PR 생성 + auto merge — 개인(origin)
gh pr create -R mygithub05253/unstructured-data-processing-final-project \
  --base main --head feat/member-shinjiyoung \
  --title "feat(신지영): 0519 전처리" \
  --body "신지영 0519 전처리 노트북·HTML 추가 (365 SUCCESS, Kiwi)"
gh pr merge -R mygithub05253/unstructured-data-processing-final-project \
  feat/member-shinjiyoung --merge --delete-branch

# (6) PR 생성 + merge — 협업(team)
gh pr create -R gc-unstructured-data-processing/main \
  --base main --head feat/member-shinjiyoung \
  --title "feat(신지영): 0519 전처리" \
  --body "신지영 0519 전처리 노트북·HTML 추가"
gh pr merge -R gc-unstructured-data-processing/main \
  feat/member-shinjiyoung --merge --delete-branch

# (7) 로컬 main 동기화
git checkout main
git pull origin main
git pull team   main
```

> **gh 없이 웹으로**: (4) push 후 GitHub 저장소 → "Compare & pull request" → base `main`, compare 해당 branch → Create PR → (auto-merge 켜려면) "Enable auto-merge" 또는 "Merge pull request". 양쪽 레포 각각 반복.
> **auto merge 조건**: 레포에 branch protection(필수 리뷰/체크)이 걸려 있으면 `--auto`로 예약 merge되고 조건 충족 시 자동 병합됩니다. 보호 규칙이 없으면 `--merge`로 즉시 병합됩니다.

### 나머지 멤버 — 같은 패턴, 경로/메시지만 교체

| branch | stash 경로 | commit 메시지 |
|---|---|---|
| `feat/member-kimhyesung` | `members/김혜성/` | `feat(김혜성): 0519 수집+전처리 (381 SUCCESS, seed 30/30)` |
| `feat/member-kimjiwoo` | `members/김지우/` | `feat(김지우): 0519 풀파이프 (210 firm-year, exp_B/E/F, 부호역전)` |
| `feat/donghoon-integrated-v1` | `members/이동원/` | `feat(이동원): 통합 노트북 v1 + 폴더 정리(_legacy)` |
| `feat/team-comparison-v0.1` | `members/_integrated/` | `docs(_integrated): 팀 비교 대시보드·git 가이드 v0.1` |

각 멤버 블록 실행 시 (1)~(7) 반복. **순서 권장**: 신지영 → 김혜성 → 김지우 → 이동원 → 대시보드.

> **이동원 branch 주의**: 폴더 정리(mv)로 구버전이 `_legacy/`로 이동되어 git에 "삭제+추가(rename)"로 잡힙니다. `git add members/이동원/`로 한 번에 stage하면 정리 결과가 그대로 반영됩니다.

## 2. 기타 기존 변경 (docs·data·README 등) 처리

stash에는 이전 세션의 미커밋 변경(`docs/professor_md/*`, `data/seed_dictionary.csv`, 루트 `README.md`, `docs/supplements/*` 수정·삭제 등)도 함께 들어 있습니다. 멤버 branch들을 모두 처리한 뒤, 남은 변경을 정리 branch로 올립니다.

```bash
git checkout -b chore/sync-misc-0521 main
git stash pop                           # 남은 변경 전부 working tree로 복원
git add -A                              # 삭제(D)도 함께 stage됨
git status                              # ⚠️ 삭제 목록 꼭 확인 (의도된 삭제인지)
git commit -m "chore: docs·data·README 동기화 + 구버전 정리"
git push -u origin chore/sync-misc-0521
git push    team   chore/sync-misc-0521
# PR + merge (양쪽, 1번과 동일 방식)
git checkout main && git pull origin main && git pull team main
```

> **중요**: `git status`에서 삭제(D)로 잡힌 파일(`docs/supplements/*.html` 4개, 이동원 구 `01_collection.ipynb` 등)이 **정말 지워도 되는지** 한 번 확인 후 commit하세요. 살리고 싶은 파일은 `git checkout -- <경로>`로 복원.

## 한 번에 처리(빠른 대안, 멤버 분리 없이)

멤버별 분리 없이 통째로 올리려면:

```bash
git stash pop 2>/dev/null || true       # (stash 했다면) 복원
git checkout -b feat/integrate-0521
git add -A
git status                              # 삭제 목록 확인
git commit -m "feat: 0521 통합 — 멤버 파일·통합 v1·대시보드 + 폴더 정리"
git push -u origin feat/integrate-0521
git push    team   feat/integrate-0521
gh pr create -R mygithub05253/unstructured-data-processing-final-project --base main --head feat/integrate-0521 --title "0521 통합" --body "멤버 4명 + 통합 v1 + 대시보드"
gh pr merge  -R mygithub05253/unstructured-data-processing-final-project feat/integrate-0521 --merge --delete-branch
gh pr create -R gc-unstructured-data-processing/main --base main --head feat/integrate-0521 --title "0521 통합" --body "멤버 4명 + 통합 v1 + 대시보드"
gh pr merge  -R gc-unstructured-data-processing/main feat/integrate-0521 --merge --delete-branch
git checkout main && git pull origin main && git pull team main
```

논리 단위 추적이 필요하면 1번(멤버별), 빠르게 끝내려면 이 방법을 쓰세요.
